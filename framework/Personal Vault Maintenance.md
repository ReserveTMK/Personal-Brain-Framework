# Personal Vault Maintenance

Maintenance protocol for Personal-Brain.

## Goal

Keep the brain small, current and legible. Prefer reconciliation over accumulation and useful doorways over elaborate taxonomy.

## Structural work

Before a substantial restructure:
1. read the affected domain doorway and current notes;
2. identify canonical homes and live systems;
3. change the smallest structure that solves the navigation problem;
4. run structural checks; and
5. test the main retrieval path.

Routine canonical-note updates do not require proposal ceremony.

## Domain doorway standard

Each meaningful domain index should tell a future memoryless agent enough to enter without broad search. Include, where useful:
- scope;
- strongest canonical notes/sub-workspaces;
- live sources owning volatile truth;
- read order; and
- write-back routing.

Small domains can stay short.

## Workspace standard

Use a nested workspace only for a topic with multiple durable artefacts or sustained moving parts. Its index should normally provide current state, read order, canonical/source ownership, important artefacts and write-back routing.

## Health checks

Check for:
- missing core metadata where the repository uses it;
- invalid authority/lifecycle vocabulary;
- broken/ambiguous internal links;
- durable notes unreachable from domain navigation;
- current-work items whose canonical lifecycle disagrees;
- competing agent instructions;
- stale source-routing claims;
- duplicate “latest/final/v2” canonical candidates.

Warnings require judgement; they do not authorise deletion.

## Retrieval smoke tests

After meaningful structural change, test real questions from the person's actual content:
- an ongoing personal matter;
- a durable stated preference or decision;
- current work;
- a question needing a live source;
- a general question that should not load Personal-Brain.

A healthy brain reaches the canonical context through Home → domain → topic/workspace without loading unrelated domains.

## Maintenance rhythm

Use maintenance when it has a concrete benefit. Review Inbox/current work when they contain real material, run checks after structural edits, archive only after current outcomes are promoted, and use Git for routine wording history.
